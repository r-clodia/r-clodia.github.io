Modular distro

Editions: one platform,
shaped per client.

An edition is Clodia reduced to exactly what a business needs — declared in one YAML blueprint, terraformed in one command, upgradable forever because it never forks the platform.

What a blueprint decides

Everything about the edition, nothing about the code.

🧩 Features

jobs, topics (off / single workspace / full), RAG (off / single collection / multi), channels, PWA, helpdesk. Off means no endpoint exists — real attack-surface reduction.

🤖 Agents

Ship only the native agents you need (even just one), plus the agents from your domain packs — installed and registered with their own PKI identity.

📦 Packs

Your vertical as one unit: skills + rules + MCP connectors + agent seeds. Private packs install from a local path — they never need to be published.

🔌 Integrations

Whitelist which native connectors and MCP servers exist. Optionally allow manual MCP paste for power users.

🧠 Providers

Declare the allowed AI engines (at least one). EU data-residency via AWS Bedrock supported out of the box.

🎨 Brand & language

Name, logo and accent color from the first login pixel — plus a vocabulary map: your users can see "pratiche", the platform keeps speaking "topics" internally.

Three commands

From blueprint to running edition.

# 1. terraform: compose, datadir, profile, repos, boot
$ python3 clodia-build up blueprint.yaml

# 2. the client claims the first admin from the browser (WebCrypto)

# 3. finalize: install packs, register agents, create jobs
$ python3 clodia-build finalize blueprint.yaml

The builder lives in clodia-platform/builder with example blueprints. Blueprints never contain secrets — the builder rejects them; credentials are set post-install through the vault.
